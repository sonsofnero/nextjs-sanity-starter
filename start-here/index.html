Repo Map

The extracted starter stays intentionally simple: one root workspace, one frontend app, one Sanity Studio, one `start-here` folder for visual onboarding, and a small docs area for repeatable workflow notes.

Setup Checklist

What to do first

Follow these in order. The goal is to get the starter running quickly, then neutralize the copied details before deeper project work begins.

01

Install dependencies

Install from the repo root so both workspaces use the same lockfile.

pnpm install
  • Run this once after moving the starter into its own folder.
02

Create local env files

Copy the example env files and replace the placeholders with the new project values.

cp site/.env.example site/.env.local && cp sanity/.env.example sanity/.env
  • Set the Sanity project ID, dataset, preview URL, read token, and revalidation secret.
03

Rename the project details

Update the generic starter metadata before you begin modeling the new site.

site/app/layout.tsx · sanity/sanity.config.ts · logo assets
  • Replace copied titles, descriptions, SVGs, and brand language.
04

Start both apps

Run the frontend and Studio together while you verify the copied foundation.

pnpm dev:site · pnpm dev:sanity
  • Frontend defaults to `http://localhost:3000` and Studio to `http://localhost:3333`.
05

Refresh generated types

Whenever schemas or GROQ queries change, regenerate types immediately.

pnpm typegen && pnpm type-check
  • This is the main guardrail against slice contract drift.

First Cleanup Pass

What still needs attention

Because this starter began as a real project extraction, these are the items worth cleaning up before you treat it as the canonical boilerplate.

1

Keep future domain packs optional and outside the default content model so the base starter stays broadly reusable.

2

Replace project-specific copy, metadata, and logo assets that were intentionally carried over in the first pass.

3

Audit the seeded slices and remove anything that should not live in the long-term canonical starter.

4

Confirm Studio desk structure, singleton handling, and default documents still fit the next project.

5

Run a final `pnpm check` and smoke test after cleanup.

Guardrail

Keep schema, query, and component changes in lockstep.

Most drift in this stack happens when one part of the slice contract changes without the other two. Keep the workflow explicit every time you touch a slice.

schema → query → component → registry → typegen
